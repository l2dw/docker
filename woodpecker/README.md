# Woodpecker CI

[Woodpecker](https://woodpecker-ci.org) server + agent (`woodpeckerci/woodpecker-server:v3`, `woodpecker-agent:v3`) on `dokploy-network`. UI on HTTP **8000**; agent talks gRPC to the server on **9000** (internal). Agent needs the Docker socket to run pipeline steps.

Docs: [Docker Compose install](https://woodpecker-ci.org/docs/administration/installation/docker-compose) · [GitHub forge](https://woodpecker-ci.org/docs/administration/configuration/forges/github) · [Gitea/Forgejo](https://woodpecker-ci.org/docs/administration/configuration/forges/gitea)

`.env` is **not** read by `docker stack deploy` alone — use Make:

```sh
make woodpecker-setup \
  WOODPECKER_HOST=https://example.com/woodpecker \
  WOODPECKER_DOMAIN=example.com \
  WOODPECKER_BASE_PATH=/woodpecker
make woodpecker-stack-up
# or
make woodpecker-compose-up
```

On the `woodpecker` branch, root `README.md` / `compose.yml` / `docker-compose.yml` are symlinks into `woodpecker/`.

| File | Labels |
|------|--------|
| [`compose.yml`](compose.yml) | Full stack, none |
| [`docker-compose.yml`](docker-compose.yml) | Full stack, Traefik + Homepage on server |
| [`server-compose.yml`](server-compose.yml) | `woodpecker-server` only (+ labels) |
| [`agent-compose.yml`](agent-compose.yml) | `woodpecker-agent` only (no HTTP labels) |

Deploy one role (Compose):

```sh
docker compose -f woodpecker/server-compose.yml --env-file woodpecker/.env up -d
docker compose -f woodpecker/agent-compose.yml --env-file woodpecker/.env up -d
```

The agent expects an already running server reachable at `WOODPECKER_AGENT_SERVER` (default `woodpecker-server:9000` on the overlay).

## Base path

Supported via **`WOODPECKER_HOST`** (full public URL, no trailing slash) and Traefik **`WOODPECKER_BASE_PATH`**. Defaults include the project path:

- Default: `WOODPECKER_BASE_PATH=/woodpecker` and `WOODPECKER_HOST=http://example.com/woodpecker`
- Root on a dedicated subdomain: `WOODPECKER_BASE_PATH=/` and `WOODPECKER_HOST=https://ci.example.com`

Keep `WOODPECKER_HOST` and Traefik `PathPrefix` aligned. OAuth callback: `${WOODPECKER_HOST}/authorize`.

## Forge (OAuth)

Enable **one** forge:

**GitHub** (default): OAuth App → callback `https://<host>/authorize`. Set `WOODPECKER_GITHUB_CLIENT` / `WOODPECKER_GITHUB_SECRET`. Leave `WOODPECKER_GITHUB_PUBLIC_ONLY=false` for private repos.

**Gitea / Forgejo**: set `WOODPECKER_GITHUB=false`, `WOODPECKER_GITEA=true`, plus `WOODPECKER_GITEA_URL` / `CLIENT` / `SECRET`.

## Required env

| Variable | Notes |
|----------|--------|
| `WOODPECKER_HOST` | Public URL including base path (default `http://example.com/woodpecker`) |
| `WOODPECKER_DOMAIN` | Traefik `Host()` |
| `WOODPECKER_BASE_PATH` | Traefik `PathPrefix` (default `/woodpecker`) |
| `WOODPECKER_AGENT_SECRET` | Shared server↔agent (`openssl rand -hex 32`, auto-generated by setup) |
| `WOODPECKER_SERVER_ENV_FILE` / `WOODPECKER_AGENT_ENV_FILE` | Compose `env_file` (default `.env.example`, path relative to `woodpecker/`). `environment:` wins on conflicts. Use `.env` in prod |
| OAuth client/secret | GitHub or Gitea/Forgejo depending on forge |

`env_file` applies to **Compose** (`compose-up` / `docker compose -f …`). For Swarm `stack deploy`, rely on Make-exported root `.env` + `environment:` interpolation (`env_file` is not applied the same way by `docker stack deploy`).

Agent placement defaults to Swarm **manager** (Docker socket). HTTP port is not published; Traefik routes the UI. gRPC stays on the overlay (`woodpecker-server:9000`) for the in-stack agent.
